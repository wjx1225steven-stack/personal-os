# PERSONAL OS（人生升级计划）

一个面向个人成长的轻量任务管理网页应用。V1.1 使用原生 HTML、CSS 和 JavaScript，任务保存在当前浏览器中。

## 功能

- 今日概览：今日任务数、已完成数和完成率
- 六大成长模块：执行、读书与心智、国际化、AI 能力、身体训练、个人品牌
- 任务管理：新建、编辑、删除、搜索、筛选与完成状态切换
- 本地存储：刷新或关闭网页后，任务仍会保留
- 数据迁移：支持 JSON 格式的完整导出与导入
- 响应式布局：适配电脑、平板和手机
- 隐私友好：无外部 API、无账号系统、无个人信息上传

## 在 Mac 上运行

### 方法一：直接打开

在 Finder 中双击 `index.html` 可以打开页面。文件网址的存储与锁权限由浏览器决定。如果出现无法保存的提示，请先从原入口导出任务，再使用下面的本地服务器方式。

### 方法二：启动本地服务器（推荐）

1. 打开 Mac 的“终端”应用。
2. 使用 `cd` 进入项目目录。
3. 运行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

4. 在浏览器访问 `http://localhost:8000`。
5. 结束运行时，回到终端按 `Control + C`。

本地服务器更接近真实网站的运行方式，后续学习和调试也更方便。

## 使用说明

- 点击右上角“新建任务”，填写名称、所属系统、日期和优先级。
- 点击任务左侧方框，切换完成状态。
- 鼠标移到任务上，可看到编辑与删除按钮；手机端会始终显示。
- 点击侧栏中的成长系统，可查看该系统的任务并进行筛选或搜索。
- 在“数据管理”中导出 JSON 备份；导入时会替换当前任务，请先确认已有数据是否需要备份。
- 键盘未处于输入框时，按 `N` 可快速新建任务。

## 数据存储说明

任务使用浏览器的 `localStorage` 保存，键名为 `personal-os-tasks-v1`。这意味着：

- 刷新页面后数据不会丢失。
- 不同浏览器、不同设备的数据不会自动同步。
- 清除浏览器网站数据可能同时删除任务。
- 建议定期通过“数据管理 → 导出数据”保存备份。

### 从 V1.0 升级或迁移

先在原来的浏览器和网址导出一次 JSON，关闭旧版标签页，再从同一入口打开 V1.1。已有的有效任务会直接读取，升级时保留原记录。请使用支持 Web Locks 的现代浏览器，通过 localhost 或 HTTPS 打开，以便多个页面安全保存。

双击文件、本地服务器和 GitHub Pages 使用不同的存储环境。更换浏览器、网址或端口时，先从旧入口导出，再到新入口导入。确认框会显示现有数量和备份数量。导入空备份也会替换当前列表。

### V1.1 修复与恢复

- 任务标题和备注按文字显示，包括引号和尖括号。导入会检查完整格式、版本、真实日期、完成状态及 ID 唯一性，遇到坏记录会指出位置。
- 保存成功后才更新列表。保存失败时可以保留输入并重试。其他页面修改了同一任务时，请复制需要保留的草稿，重新打开最新任务后再编辑。
- 显示存储损坏提示时，先在“数据管理”中导出原始内容，再导入一份有效备份。恢复操作会在浏览器中另存损坏的原文；浏览器拒绝读取时，需先恢复该网站的存储权限。
- 首次示例固定在创建日。首页在本地午夜、唤醒后重新获得焦点或切回页面时更新。模块进度条、今日列表展开状态和手机抽屉焦点已修复。
- 如需恢复旧版源码，请先导出当前任务，再将 `_backups/personal-os-v1.0.zip` 解压到单独文件夹。代码压缩包只包含五个项目文件，任务备份由“导出数据”生成。

### 运行回归测试

在本地服务器运行期间打开 [浏览器回归页](_tests/regression.html)，点击“运行回归”，保持测试页在前台直至出现“全部通过”。测试会临时创建两个同源页面，用独立的随机存储键模拟用户操作并在结束时清理。测试时钟和存储故障仅对测试页面生效。

## 部署到 GitHub Pages

当前版本已经使用相对路径，可直接部署静态网站。验收通过后可按以下步骤操作：

1. 在 GitHub 新建仓库，并将 `index.html`、`styles.css`、`app.js` 放在发布目录根部。源码压缩包、回归页和个人 JSON 备份均可留在本地。
2. 打开仓库的 `Settings → Pages`。
3. 在 `Build and deployment` 中选择 `Deploy from a branch`。
4. 分支选择 `main`，文件夹选择 `/ (root)`，保存。
5. 等待 GitHub 完成部署，然后访问 Pages 提供的网址。

注意：GitHub Pages 只托管网页文件。任务仍保存在每位访问者自己的浏览器中，不会上传到 GitHub。
